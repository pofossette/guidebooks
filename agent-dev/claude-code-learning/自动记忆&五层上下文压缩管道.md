1. **Claude Code 如何保证“自动记忆质量”**
2. **五层渐进式压缩管道如何工作**

## 一、自动记忆质量保障机制

```mermaid
flowchart TD
    A[用户持续对话/执行任务] --> B[Query Loop 维护完整会话状态]
    B --> C[监控上下文预算<br/>token、输出预留、阈值]
    C --> D{是否接近上下文上限?}

    D -- 否 --> E[继续正常推理与工具调用]
    E --> F[更新当前工作集]
    F --> C

    D -- 是 --> G[进入 Compact 流程]
    G --> H[预清洗上下文<br/>移除图片/大工具结果/可重注入附件]
    H --> I[模型生成结构化摘要]
    I --> J[写入 Compact Boundary<br/>标记已压缩历史]
    J --> K[重注入关键工作集<br/>附件/技能/MCP delta/重要文件状态]
    K --> L[恢复 Query Loop]

    L --> M[Post-sampling Hook]
    M --> N{是否满足记忆更新条件?}

    N -- 否 --> O[继续当前会话]
    N -- 是 --> P[启动 Forked Memory Agent]
    P --> Q[更新 Session Memory 文件]
    Q --> R[完整回合结束后抽取 Durable Memory]
    R --> S[写入 Auto-memory 目录]

    S --> T[后续会话检索相关记忆]
    T --> U[记忆重新进入上下文装配]
```

### 这张图想表达什么

核心不是“模型自己记住”，而是四个模块一起保证质量：

* **模型**：负责摘要、提炼、改写
* **Runtime**：负责何时触发压缩、何时恢复
* **Attachments/工作集系统**：负责把重要上下文重新挂回去
* **Memory 存储层**：负责把可复用信息沉淀成外部记忆

所以它更像：

**模型 = 压缩器**
**Runtime = 调度器/质控器**
**Attachments = 工作集装配器**
**Memory Store = 长期存储器**

## 二、五层渐进式压缩管道

```mermaid
flowchart TD
    A[原始 Transcript/工具结果/附件/文件状态] --> B[第一层：预算感知与阈值触发]
    B --> B1[计算 warning/error/auto-compact/blocking limit]
    B1 --> C[第二层：预清洗与污染隔离]
    C --> C1[去掉图片、超长工具输出、后续会重注入的附件]
    C1 --> D[第三层：结构化摘要与边界固化]
    D --> D1[模型压缩历史]
    D1 --> D2[生成 compact summary]
    D2 --> D3[写入 compact boundary]
    D3 --> E[第四层：关键工作集再注入]
    E --> E1[重新加入仍然必要的上下文]
    E1 --> E2[如 CLAUDE.md / memory files / task delta / MCP delta / 重要附件]
    E2 --> F[第五层：记忆沉淀与长期抽取]
    F --> F1[更新 Session Memory]
    F1 --> F2[抽取 Durable/Auto Memory]
    F2 --> G[后续会话按需检索与再利用]
```

## 三、把“五层”再翻成更容易理解的人话

### 第 1 层：先判断“现在该不该压”

```mermaid
flowchart LR
    A[当前上下文增长] --> B[检查 token 预算]
    B --> C{是否逼近阈值?}
    C -- 否 --> D[继续对话]
    C -- 是 --> E[触发 compact]
```

这一层解决的是：**时机问题**。
压太早，丢细节。压太晚，直接爆窗。

---

### 第 2 层：先把垃圾和噪音清掉

```mermaid
flowchart LR
    A[待压缩上下文] --> B[识别噪音]
    B --> C[移除大工具结果]
    B --> D[移除图片/文档占位]
    B --> E[移除稍后可重注入附件]
    C --> F[得到干净语义上下文]
    D --> F
    E --> F
```

这一层解决的是：**别让模型拿脏输入做摘要**。
否则摘要器会把注意力浪费在不该记的内容上。

---

### 第 3 层：把长历史压成“可恢复”的结构化摘要

```mermaid
flowchart LR
    A[干净后的历史消息] --> B[构造 compact prompt]
    B --> C[模型生成摘要]
    C --> D[写入 compact summary]
    D --> E[设置 compact boundary]
```

这一层解决的是：**不是随便写一段总结，而是生成带边界的会话状态**。
这样系统知道哪些历史已经被压缩。

---

### 第 4 层：把真正重要的工作集放回去

```mermaid
flowchart LR
    A[压缩后的简短历史] --> B[识别当前任务仍依赖的信息]
    B --> C[重注入关键附件]
    B --> D[重注入 memory files]
    B --> E[重注入 task/MCP/agent delta]
    C --> F[形成可继续工作的上下文]
    D --> F
    E --> F
```

这一层最关键。
因为**摘要只保留“故事梗概”还不够，系统还得保留“继续干活需要的工作集”**。

---

### 第 5 层：把临时上下文变成长期记忆

```mermaid
flowchart LR
    A[当前会话的重要信息] --> B[更新 Session Memory]
    B --> C[回合结束后抽取长期记忆]
    C --> D[写入 Auto-memory 目录]
    D --> E[未来会话按需检索]
```

这一层解决的是：**从“当前能继续聊”升级到“以后还能复用”**。

---

## 四、两部分之间的关系

```mermaid
flowchart TD
    A[自动记忆质量] --> B[不是只靠模型]
    B --> C[需要摘要能力]
    B --> D[需要阈值控制]
    B --> E[需要工作集重注入]
    B --> F[需要外部记忆存储]
    B --> G[需要权限受限的记忆代理]

    C --> H[五层渐进式压缩管道]
    D --> H
    E --> H
    F --> H
    G --> H
```

也就是说：

* **“自动记忆质量”** 是目标
* **“五层渐进式压缩管道”** 是实现这个目标的主干机制

---

## 五、一句话总结

如果只靠模型能力，Claude Code 最多做到“会总结”。
但它真正做到的是：

**会在对的时机压缩 → 压缩前清洗噪音 → 压成可恢复结构 → 把关键工作集补回 → 把值得保留的信息沉淀成长期记忆。**

所以它不是“模型自动记忆”，更准确说是：

**模型压缩 + runtime 调度 + 工作集重注入 + 外部 memory 存储** 的联合系统。
