# Anthropic：构建有效的人类-Agent 团队

> 来源：[Building effective human-agent teams](https://claude.com/blog/building-effective-human-agent-teams)
>
> 发布日期：2026-06-24
>
> 类型：官方博客总结

## 一句话摘要

Anthropic 认为，Agent 正从“一人一个聊天窗口”的单人模式，转向多人和多个 Agent 共享工作空间、上下文与目标的“多人协作”模式。成败的关键不只是模型能力，还包括信息透明、角色分工、目标管理、质量验证和逐步建立信任。

## 文章主线

### 什么是多人协作 Agent

这里的 multiplayer agents 指能够同时与多个不同的人协作的 AI 模型。它们不只是被动响应单次请求，还需要具备：

- 持久记忆，能够记住团队目标和工作背景。
- 独立凭证、技能和工具权限，能够在实际工作环境中执行任务。
- 持续访问团队信息的能力，能够理解组织如何工作并采取行动。

这些能力通常依托团队共享的工作空间，例如 Slack、代码仓库、文档库和会议记录。

## 四条实践原则

### 1. 公开工作，提供广泛上下文

Agent 只能从可访问、可搜索的文本中理解组织。一个关键判断是：**没有写下来且不可搜索的信息，对 Agent 来说就不存在。**

文章建议：

- 预先定义少量清晰的安全边界，而不是为每个频道、文档和线程临时决定权限。
- 默认让组织内部的新频道公开，并确保决策进入频道、文档和会议记录。
- 按照 Agent 也是文档主要消费者的要求，改进文档和会议记录的可检索性。
- 为敏感信息保留私密的人机交互路径，不把所有信息都无条件公开。

公开上下文可以减少重复工作：Agent 能看到已经否决的方案、其他团队验证过的模式，以及人类容易错过的大量相关信息。

### 2. 为每个人和每个 Agent 定义角色，并配备正确工具

团队应共享一份 roster、一套工作产物和一个工作空间。每个成员都要明确：

- 负责什么任务和结果。
- 拥有哪些凭证、技能和工具。
- 哪些决策必须由人类完成。
- 哪些任务可以委托给其他专业 Agent。

清晰的角色能避免人们各自运行私有 AI，造成重复劳动和团队上下文割裂。文章提到，可以用 skill 文件描述 Agent 的角色和范围，并在项目变复杂时增加专门的 Agent，例如发布管理 Agent。

人类通常负责战略、目标和需要判断取舍的决策；Agent 可以共享代码库的日常维护、反馈分类、计划、编码、变更审查和状态汇报等工作。

### 3. 用北极星目标让 Agent 更主动

人类需要先讨论、确定并写下一个与业务使命相关的长期目标，也就是 north star。然后明确指定哪些 Agent 具备足够的技能和信任，可以主动提出新的工作流或项目。

重点不是让所有 Agent 都自主规划，而是让合适的 Agent 在清晰方向下发现机会。例如，目标是让产品 onboarding 更有帮助时，Agent 可以主动建议改进错误提示文案，并通过结果验证建议是否有效。

### 4. 随时间建立信任，逐步扩大自治

Agent 的权限应该根据已证明的可靠性逐步增加，而不是一开始就全面放开。推荐的过程是：

1. 初期人工审查每项工作，了解 Agent 的能力和缺陷。
2. 为工作产物建立测试、评分标准、风格指南和检查清单。
3. 让一个 Agent 执行任务，另一个 Agent 验证结果，即 Doer-Verifier 模式。
4. 要求 Agent 复盘遗漏和错误，并把经验沉淀下来。
5. 按任务类型记录已经获得的自治权，连续成功后再扩大范围。

即使代码有测试，技术文档、研究报告和数据分析也可以通过 rubric、规范和事实核查来验证。涉及重大取舍的决策应持续保留人在环。

## 人类注意力是稀缺资源

当 Agent 数量增加后，瓶颈往往不再是 Agent 能做多少，而是人类能审查和决策多少。文章建议：

- 批量整理问题，减少频繁打断。
- 在提问时重复关键上下文，降低人类接手成本。
- 只把最重要的事项升级给人类。
- 控制每个 Agent 每天的工作量和需要人工审核的条目数。
- 必要时设置专门的 Agent 负责整理、合并和升级沟通。

这些限制既能保持审核质量，也能避免人类逐渐失去对关键领域的理解和判断能力。

## 落地时必须解决的问题

| 问题 | 需要建立的机制 |
| --- | --- |
| 广泛上下文与隐私冲突 | 按工作区、数据域或团队定义安全边界；敏感任务使用私密路径 |
| 角色不清和重复劳动 | 建立人类与 Agent 的 roster、责任范围和唯一 owner |
| Agent 不知道团队真实方向 | 把决策、优先级和北极星目标写入共享文档与工作空间 |
| 输出质量不可控 | 为不同工作产物建立测试、rubric、风格指南和事实核查 |
| 自治权放得过早 | 按任务类型逐步授权，并保留高风险决策的人类审批 |
| 人类被大量问题淹没 | 设计批量提问、摘要、升级规则和审核量上限 |
| 模型升级后行为变化 | 定期重测任务，重新评估提示词、护栏和自治范围 |

## 实用检查清单

- [ ] Agent 和人类需要的信息是否都公开、可搜索且权限正确？
- [ ] 是否能写出完整的团队 roster，并说明每个成员负责什么？
- [ ] 每个 Agent 是否拥有完成职责所需的工具和凭证？
- [ ] 关键工作产物是否有测试、rubric 或其他可复核标准？
- [ ] 团队是否有所有成员都能引用的北极星目标？
- [ ] 是否按任务类型记录自治权限，并定义人工升级条件？
- [ ] 是否控制了 Agent 产生的通知、问题和人工审核负担？

## 关键启示

这篇文章的核心并不是“增加更多 Agent”，而是把成熟的人类团队习惯应用到人机团队：清晰目标、明确分工、共享文档、共同质量标准、持续反馈和渐进式授权。Agent 越多，这些基础治理越不能省略；因此，Agent 团队建设首先是组织与协作机制设计，其次才是模型和 Prompt 设计。
