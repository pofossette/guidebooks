# Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

## 来源

- 论文：[arXiv](https://arxiv.org/abs/2005.11401)
- 本库说明：[RAG 与 RCG 区分](../../../rag/rag&rcg区分.md)

## 结论

RAG 将预训练生成模型的参数记忆与外部检索索引的非参数记忆结合：系统先召回相关资料，再让模型基于问题和检索上下文生成回答。这一范式为知识密集型问答引入了可更新的外部知识，但检索内容通常仍是增强材料，而非生成内容的绝对边界。

## 问题与设定

知识密集型任务需要事实知识，而仅依赖模型参数知识会受到知识覆盖与更新能力的限制。RAG 的设定是在回答前访问向量库、全文索引或知识库等外部索引，召回相关文档片段，并把它们与用户问题共同交给生成模型。

## 核心方法/设计

典型流程为：文档切分、embedding 向量化并写入索引；将用户问题向量化后执行 Top-K 检索；可选地重排候选片段；最后拼接问题与检索上下文，由大语言模型生成答案。

该设计中，检索器负责提供外部知识，生成模型负责整合检索材料、语言表达与推理能力。实现关注点包括切分策略、embedding 模型、召回质量、重排、Prompt 模板、引用生成和上下文窗口管理。

## 评估内容与使用方式

给定问题后，先检索相关资料，再以“问题 + 检索内容”构造 Prompt 生成回答。它适合企业知识助手、产品客服、技术文档问答、营销内容生成和通用研究助手等允许模型适度推理、补充且重视表达自然度的场景。

本库来源将 RAG 与强调证据边界的 RCG 对照：RAG 的评估和验收除回答质量外，还应关注检索是否正确、上下文是否受污染，以及模型是否补充了检索材料之外的内容。限定来源未提供该论文的具体实验数据，本文不补充数值性结论。

## 局限与边界

- RAG 会使用模型的参数知识与推理能力，因而不能天然保证答案只来自检索材料。
- 检索错误、上下文污染和模型自由补充都会影响事实可靠性。
- 可追溯性取决于引用设计；对答案必须有依据、错误成本高的场景，需进一步采用证据筛选、拒答和一致性校验等更严格约束。
