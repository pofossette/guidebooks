# LightRAG: Simple and Fast Retrieval-Augmented Generation

## 来源

- 论文：[arXiv](https://arxiv.org/abs/2410.05779)
- 本库分析：[LightRAG](../../../rag/lightrag.md)

## 结论

LightRAG 是以实体--关系图谱为核心索引、以向量检索进行召回、再由 LLM 完成关键词分解与答案生成的图增强 RAG。它通过低层与高层双层检索，同时面向局部事实查询和全局主题查询，并强调增量更新。

## 问题与设定

传统只检索文本块的 RAG 对局部语义召回较直接，但对跨文档关系、主题和全局关联的组织能力有限；图方法又可能引入较高的图遍历与报告生成开销。LightRAG 的设定是从文档块中抽取实体和关系，建立可回溯源文本的图谱与向量索引，并在查询阶段按问题粒度组合使用它们。

## 核心方法/设计

建库时，系统将文档切块，为文本块建立向量索引，并调用 LLM 抽取实体、关系及描述；随后合并去重，将实体和关系写入图存储和对应向量存储，同时保留它们到源文本块的追踪。其状态由 KV 存储、向量存储、图存储和文档状态存储共同维护。

查询时，LLM 从问题中提取低层关键词与高层关键词：低层侧重具体实体、属性和关系，高层侧重主题和全局关联。`local` 模式检索实体，`global` 模式检索关系，`hybrid` 融合两者，`naive` 直接检索文本块，`mix` 在融合图谱检索的同时加入文本块向量检索。系统再合并、去重、可选重排并按 token 预算构造包含实体、关系、文本块与引用的上下文。

## 评估内容与使用方式

来源记录论文与 NaiveRAG、RQ-RAG、HyDE、GraphRAG 等基线在农业、计算机科学、法律和混合数据集上进行了 win-rate 对比，并说明 README 复述了其在多个数据集和评估维度上优于这些基线的结果；限定来源未给出具体分数，本文不补充数值性结论。

使用时可按问题选择模式：具体实体或事实查询使用 `local`，主题、趋势和整体关系使用 `global`，需要同时整合事实与主题时使用 `hybrid` 或 `mix`；来源建议在启用 reranker 时优先使用 `mix`。图谱质量尚未验证时，可先以 `naive` 作为基线，再与 `mix` 比较。

## 局限与边界

- 图谱质量依赖文档切分、LLM 的实体关系抽取及后续合并去重质量。
- 增加图、实体、关系和源文本追踪后，存储与索引维护的工程复杂度高于只检索文本块的 RAG。
- 全局与局部检索、三路上下文合并及 token 预算都需要按数据集和任务验证；来源没有提供可直接外推的固定参数或实验数值。
