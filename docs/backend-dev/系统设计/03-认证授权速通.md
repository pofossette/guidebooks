# 03. 认证授权速通

这篇参考 `JavaGuide` 里认证授权相关内容来写，目标是用尽量通俗的话把这条线讲清楚。

很多人一提安全，就开始说 JWT、OAuth2、SSO，但其实第一步是先把三个词分清：

- 认证
- 授权
- 会话 / 令牌

## 一、认证和授权到底有什么区别

### 1. 认证

认证是在回答：

**你是谁？**

例如：

- 用户名密码登录
- 手机验证码登录
- 扫码登录
- 单点登录

### 2. 授权

授权是在回答：

**你能做什么？**

例如：

- 普通用户能看内容
- 管理员能删内容
- 财务角色能看账单

所以最通俗的理解是：

- 认证先确认身份
- 授权再决定权限

## 二、Session 和 JWT 是什么关系

这两个经常被拿来对比。

### 1. Session

思路是：

- 登录成功后，服务端保存一份会话状态
- 浏览器带着 Session ID 过来
- 服务端根据 ID 找到这份会话

你可以把它理解成：

**身份信息主要存在服务端。**

### 2. JWT

思路是：

- 登录成功后，服务端签发一个 token
- 客户端后续每次带上 token
- 服务端验证 token 签名和有效期

你可以把它理解成：

**身份信息主要由 token 自带，服务端重点做校验。**

## 三、Session 和 JWT 怎么选

### Session 更适合

- 传统 Web 网站
- 服务端渲染项目
- 更容易做会话失效控制

### JWT 更适合

- 前后端分离 API
- 多端接入
- 微服务或网关统一鉴权

但不要把 JWT 神化。

JWT 的问题也很现实：

- 签发后不容易立刻作废
- token 泄露风险大
- 负载塞太多信息会变臃肿

## 四、密码登录最基本该怎么做

至少做到这些：

1. 密码绝不能明文存储
2. 要用密码哈希，不是普通加密
3. 要有限流、防暴力破解和错误次数控制
4. 要考虑验证码、二次验证或风控

很多初学者会把“加密”和“哈希”混为一谈。

这里先记一句：

- 密码存储主要靠哈希
- 传输安全主要靠 HTTPS

## 五、OAuth 2.0 是在解决什么问题

OAuth 2.0 不是“登录协议”的简单同义词。

它主要解决的是：

**用户想让第三方应用代表自己访问某个资源，但又不想把密码直接给第三方。**

典型例子：

- 用 GitHub 登录别的网站
- 用微信登录应用
- 企业内部系统接入统一身份平台

所以 OAuth2 的核心是“授权委托”。

## 六、OIDC 又是什么

如果说 OAuth2 更偏“授权”，那 OIDC 是在它之上补了一层“身份”。

它更适合：

- 做登录
- 获取用户身份信息
- 统一身份体系

所以面试里常见的一句说法是：

- OAuth2 偏授权
- OIDC 偏身份认证

## 七、SSO 是在解决什么问题

SSO 是单点登录。

它解决的是：

**用户在多个系统之间，不想每个系统都重新登录一次。**

常见于：

- 企业后台
- 内部平台矩阵
- 多子系统统一账号体系

## 八、授权模型最常见的是哪几种

### 1. RBAC

基于角色的访问控制。

思路是：

- 先给人分角色
- 再给角色分权限

比如：

- 普通用户
- 审核员
- 管理员

这是最常见、最好落地的方式。

### 2. ABAC

基于属性的访问控制。

它不只看角色，还看：

- 用户属性
- 资源属性
- 环境属性

例如：

- 只有本部门经理才能看本部门数据
- 只有工作时间内才能执行某操作

ABAC 更灵活，但也更复杂。

## 九、后端系统里鉴权一般放在哪

常见位置有三层：

### 1. 网关层

做：

- 基础 token 校验
- 黑名单
- 限流

### 2. 应用层

做：

- 业务权限判断
- 资源级权限控制

### 3. 数据层

必要时再做：

- 行级隔离
- 租户隔离

不要把所有授权都丢给前端。前端只能做体验控制，真正的安全边界必须在后端。

## 十、常见风险点

### 1. Token 泄露

### 2. 权限校验只做了页面隐藏，没做接口校验

### 3. 角色很多但权限模型混乱

### 4. 管理后台缺少审计日志

### 5. 刷新 token、登出、封禁流程设计不完整

## 十一、最小可用的认证授权方案怎么做

对很多中小型后端项目，一个务实方案通常是：

1. 用户名密码登录
2. 密码哈希存储
3. HTTPS 全站传输
4. JWT 或 Session 维护登录态
5. RBAC 做接口权限控制
6. 审计关键操作

这已经比很多只会“发个 token” 的实现强很多。

## 这篇最重要的结论

认证回答“你是谁”，授权回答“你能干什么”。Session、JWT、OAuth2、OIDC、SSO、RBAC 这些词不是零散知识点，而是一整条身份与权限控制链路。
