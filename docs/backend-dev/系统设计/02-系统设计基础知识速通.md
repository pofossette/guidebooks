# 02. 系统设计基础知识速通

这篇参考 `JavaGuide` 的系统设计知识主线来写，但目标不是铺很全，而是帮你先把最常见的系统设计基础词汇串起来。

## 一、什么叫系统设计

系统设计不是“画一张架构图”。

它本质上是在回答：

- 这个系统要解决什么问题
- 它该怎么拆模块
- 数据怎么流
- 性能和稳定性怎么保证
- 出问题时怎么兜底

所以系统设计既不是纯代码问题，也不是纯运维问题，而是业务、工程、数据、性能和可靠性的综合题。

## 二、系统设计最常见的五类问题

### 1. 功能问题

系统要支持哪些核心能力。

例如：

- 用户注册登录
- 下单支付
- 消息通知
- 搜索查询

### 2. 数据问题

数据怎么建模、怎么存、怎么查。

例如：

- 用关系型数据库还是 NoSQL
- 如何做索引
- 如何分页

### 3. 性能问题

流量上来后会不会慢、会不会扛不住。

例如：

- 热点数据怎么处理
- 是否需要缓存
- 是否需要异步化

### 4. 可靠性问题

服务挂了、数据库抖了、依赖超时了怎么办。

例如：

- 重试
- 降级
- 熔断
- 主从切换

### 5. 安全和治理问题

谁能访问、谁能修改、怎么审计、怎么防攻击。

例如：

- 认证授权
- 数据脱敏
- 审计日志
- 限流防刷

## 三、系统设计里最常见的组件

### 1. 负载均衡

作用是把请求分发到多台服务实例上。

你可以先把它理解成：

**不要让所有请求只打到一台机器。**

### 2. 应用服务

承接业务逻辑。

它负责：

- 参数校验
- 业务处理
- 调数据库、缓存、队列和外部服务

### 3. 数据库

保存核心业务数据。

关系型数据库常用于：

- 用户
- 订单
- 配置
- 任务状态

### 4. 缓存

用于加速高频读取，减轻数据库压力。

常见是 Redis。

### 5. 消息队列

用于解耦和异步化。

比如：

- 下单成功后发通知
- 生成报表
- 触发异步审核

### 6. 对象存储 / 文件存储

大文件、图片、音视频通常不会直接塞数据库。

### 7. 搜索系统

当业务需要复杂检索、全文检索时，数据库不一定最合适。

## 四、几个必须先分清的概念

### 1. 高性能

重点是：

- 快
- 扛得住流量

### 2. 高可用

重点是：

- 别轻易挂
- 挂了能恢复

### 3. 一致性

重点是：

- 数据不能乱

### 4. 扩展性

重点是：

- 以后量变大了还能演进

很多人会把这几个词混在一起，但它们不是一个维度。

## 五、系统设计常用手段分别在解决什么

| 手段 | 主要解决的问题 |
|---|---|
| 缓存 | 数据库扛不住高频读 |
| 队列 | 主流程太慢、模块耦合太紧 |
| 分库分表 | 单库单表容量或吞吐受限 |
| 读写分离 | 读压力太大 |
| 限流 | 瞬时流量过高 |
| 降级 | 依赖故障时保核心功能 |
| 重试 | 临时失败可自动恢复 |
| 熔断 | 避免故障扩散 |

## 六、系统设计回答里最值得先讲的“主线”

如果你面试时不知道怎么展开，先抓这 6 个点：

1. 需求规模
2. 核心数据模型
3. 主请求链路
4. 性能瓶颈
5. 故障处理
6. 安全和监控

这 6 个点能覆盖大部分系统设计题。

## 七、通俗理解 CAP、幂等、降级、熔断

### 1. CAP

分布式系统里，不可能同时无限完美满足：

- 一致性
- 可用性
- 分区容错性

工程上不是背定义，而是接受：

**网络一出问题，就必须做取舍。**

### 2. 幂等

同一个请求重复执行多次，结果应该尽量一致。

最常见场景：

- 支付回调
- 重试请求
- 提交表单

### 3. 降级

系统压力太大或依赖挂了时，先保核心功能，牺牲次要功能。

比如：

- 推荐挂了，但下单还能用
- 评论挂了，但文章还能看

### 4. 熔断

当下游已经很不稳定时，先别继续猛打它，避免把自己也拖死。

## 八、系统设计的真实取舍

系统设计不是“最强方案比赛”，而是“当前阶段最合理方案”。

例如：

- 小系统一开始不需要分库分表
- 中等规模不一定要先上 ES
- 低并发后台系统没必要堆过多中间件

你越早理解这一点，回答就越像工程师，而不是背稿机器人。

## 九、初学者最容易犯的错误

### 1. 把系统设计理解成中间件堆砌

### 2. 不讲数据模型，只讲组件

### 3. 不讲失败路径，只讲正常流程

### 4. 不讲演进路径，默认一步到位

### 5. 不讲安全、权限和审计

## 这篇最重要的结论

系统设计的本质，不是“会不会画图”，而是你能不能围绕需求、数据、链路、瓶颈和取舍，讲出一个可落地、可演进、可排障的系统方案。
