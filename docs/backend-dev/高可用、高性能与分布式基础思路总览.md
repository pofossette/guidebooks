# 高可用、高性能与分布式基础思路总览

这篇文档的目标很简单：

**把高可用、高性能、分布式这三组最容易学散的知识，先压成一张总地图。**

很多人学到后面会有一个共同问题：

- 这个概念我见过
- 那个中间件我也听过
- 但一到系统设计或项目落地，脑子里没有主线

所以这篇不追求讲细，而是先把三条骨架立起来。

## 一、先区分这三组知识到底在回答什么问题

### 1. 高可用

高可用重点回答：

**系统出问题时，为什么不会一下子全挂。**

它关注的是：

- 稳定性
- 故障隔离
- 恢复能力

### 2. 高性能

高性能重点回答：

**系统为什么会慢，慢在哪，怎么更快。**

它关注的是：

- 吞吐量
- 响应时间
- 高峰承载能力

### 3. 分布式

分布式重点回答：

**系统拆成多个节点后，通信、协作、一致性和治理怎么做。**

它关注的是：

- 多节点协作
- 数据一致性
- 节点发现与治理

## 二、高可用的基本思路

高可用最适合先按 5 个问题理解。

### 1. 请求太多怎么办

- 限流
- 排队
- 削峰

### 2. 下游变慢怎么办

- 超时
- 重试
- 熔断
- 隔离

### 3. 核心服务挂了怎么办

- 降级
- 冗余
- 故障转移

### 4. 重复请求怎么办

- 幂等
- 防重
- 状态机

### 5. 上线前怎么证明系统扛得住

- 压测
- 监控
- 演练
- 容量评估

### 一句话记忆

高可用不是“永远不出错”，而是：

**流量太大能挡住，依赖变慢能止损，核心挂了能切换，重复请求不乱，出事前后都能验证。**

## 三、高性能的基本思路

高性能最适合按 4 层来看。

### 1. 入口层

- CDN
- 负载均衡
- 网关

### 2. 应用层

- 限流
- 异步化
- 线程池 / 连接池
- 批处理

### 3. 数据层

- 索引
- SQL 优化
- 读写分离
- 分库分表
- 冷热分离

### 4. 削峰层

- 消息队列
- 延迟处理
- 重试和补偿

### 一句话记忆

高性能不是只盯 SQL，而是：

**从入口拦流量，在应用层减等待，在数据层减成本，在削峰层摊压力。**

## 四、分布式的基本思路

分布式最适合按 4 条主线理解。

### 1. 一致性与可用性的权衡

- CAP
- BASE
- 最终一致性
- 共识算法

### 2. 跨节点通信与治理

- RPC
- 注册与发现
- API 网关
- 配置中心

### 3. 分布式数据一致性问题

- 分布式 ID
- 分布式锁
- 分布式事务

### 4. 典型中间件与落地场景

- etcd / Consul
- APISIX / Kong / Envoy
- gRPC / Connect-RPC / tRPC
- RabbitMQ / Kafka / Redis Streams / BullMQ

### 一句话记忆

分布式不是“多部署几台机器”，而是：

**系统拆开后，节点怎么找、怎么通信、状态怎么对齐、故障怎么治理。**

## 五、这三组知识之间是什么关系

很多人会把它们混着学，是因为它们在真实系统里本来就互相交叉。

例如：

- 消息队列既是高性能里的削峰手段，也是高可用里的止损手段，还是分布式里的异步协作组件
- 限流既能保护高可用，也能改善高性能
- 分布式事务和最终一致性既属于分布式，也直接影响高可用设计

所以更好的理解方式不是硬分家，而是先分清“主问题”，再看它们怎么交叉。

## 六、从系统设计视角怎么串起来

如果你在答一道系统设计题，这三条主线通常可以这样展开：

1. 先讲系统怎么拆模块和节点协作
2. 再讲高峰流量和性能瓶颈怎么处理
3. 再讲故障、重试、熔断、冗余和幂等怎么保证稳定

也就是说：

- 分布式负责“怎么拆和怎么连”
- 高性能负责“怎么更快更抗压”
- 高可用负责“怎么不轻易挂、挂了怎么收”

## 七、初学者最容易犯的错误

### 1. 把高可用学成中间件名词表

### 2. 把高性能学成 SQL 调优专栏

### 3. 把分布式学成协议和算法背诵

### 4. 不先建立问题导向，只记答案名词

## 八、推荐阅读顺序

如果你是从前端或普通后端往系统设计方向补：

1. 先看这篇总览，建立三张脑图
2. 再看 [高性能](./高性能/) 专题，先建立“请求为什么慢”的直觉
3. 再看 [高可用](./高可用/) 专题，建立“系统为什么不会一挂到底”的直觉
4. 最后看 [分布式](./分布式/) 专题，补齐多节点协作和一致性问题

## 这篇最重要的结论

高可用、高性能、分布式不是三堆独立八股，而是后端系统设计里三条互相交叉的主线：

- 高可用：系统出错时怎么稳住
- 高性能：系统流量上来时怎么扛住
- 分布式：系统拆开后怎么协作
