# 01. 高性能基础与优化思路

高性能不是“让代码跑快一点”这么简单。

它更像是在问：

- 系统哪里最耗时
- 哪个环节最先扛不住
- 用什么手段最划算地提速

## 一、系统为什么会慢

一个请求从用户发出到最终返回，可能会卡在很多地方：

- 网络传输慢
- 服务实例处理不过来
- 数据库查询慢
- 缓存没命中
- 外部依赖太慢
- 队列堆积

所以“系统慢”不是一个点，而是一条链路问题。

## 二、高性能优化最常见的五个方向

### 1. 少传

减少网络传输的数据量。

例如：

- 压缩响应
- 图片走 CDN
- 减少无用字段

### 2. 少算

减少应用层重复计算。

例如：

- 缓存热点结果
- 预计算
- 异步化非关键逻辑

### 3. 少查

减少数据库和外部依赖访问次数。

例如：

- 批量查询
- 合理索引
- 缓存

### 4. 少等

减少串行等待。

例如：

- 并行调用
- 把慢操作移出主流程
- 使用消息队列

### 5. 横向扩

单机扛不住时，通过多实例分担流量。

例如：

- 服务多副本
- 负载均衡
- 读写分离

## 三、优化时最常见的误区

### 1. 不测就优化

没有监控、没有压测、没有火焰图，只靠感觉调优，通常会浪费时间。

### 2. 只盯代码，不看架构

有些性能问题不是某段代码慢，而是链路设计不合理。

### 3. 一上来就分库分表

很多项目还没把索引、缓存、批处理、异步化做好，就急着上重型方案。

### 4. 只看平均值，不看高峰

真实系统更怕高峰打爆，而不是平均情况下慢一点。

## 四、后端系统常见性能瓶颈排序

很多项目里，瓶颈大致按这个顺序出现：

1. 数据库
2. 外部依赖
3. 网络和带宽
4. CPU 和内存
5. 锁竞争和资源争抢

这不是绝对规律，但足够适合入门判断。

## 五、一个务实的优化顺序

遇到性能问题时，建议按这个顺序排：

1. 先确认慢在哪里
2. 看是不是热点请求
3. 看数据库和缓存
4. 看外部调用和队列
5. 看服务资源和实例数
6. 最后再考虑更重的架构演进

## 六、通俗理解几个高性能关键词

### 吞吐量

单位时间内系统能处理多少请求。

### 延迟

单个请求从发出到返回花了多久。

### 并发

同一时间有多少请求同时在跑。

### 削峰填谷

高峰时先把请求接住，慢慢处理，避免瞬间打爆系统。

### 热点

极少数数据或接口占了大部分流量。

## 七、高性能优化的真实目标

不要把目标理解成“所有请求都极快”。

更现实的目标是：

- 高峰时系统不炸
- 核心接口足够快
- 成本可控
- 问题能监控和定位

## 这篇最重要的结论

高性能优化不是堆技术，而是沿着请求链路，找到最贵的环节，再用最合适的手段做减法和分流。
