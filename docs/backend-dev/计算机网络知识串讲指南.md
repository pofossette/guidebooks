# 计算机网络知识串讲指南

这篇文档参考了 `JavaGuide` 的计算机网络知识体系和 `小林 coding` 的图解网络写法，目标不是把所有协议细节背完，而是帮你在较短时间里把计算机网络的主线串起来，形成一个能用于学习、复习和面试表达的知识框架。

如果你现在的状态是：

- `HTTP` 会用，但一问到底层就容易乱
- 知道 `TCP/IP`、`DNS`、`HTTPS`、`WebSocket` 这些词，但联系不起来
- 看八股文经常是“每个点都眼熟，但脑子里没有地图”

那这篇就是给你用来补“地图”的。

## 这门课到底在讲什么

可以先把计算机网络理解成一句话：

**让两台机器上的程序，能可靠地把数据传来传去。**

但这个目标拆开之后，问题很多：

- 机器怎么找到彼此？
- 数据怎么切成一段一段发送？
- 丢了怎么办？
- 顺序乱了怎么办？
- 太快把对方打爆了怎么办？
- 浏览器输入一个网址，背后到底发生了什么？

所以网络协议本质上是在回答这些问题。

## 学网络最重要的主线

如果只记一条主线，记这个：

**分层 -> 寻址 -> 建连 -> 传输 -> 可靠性 -> 拥塞控制 -> 应用协议**

你后面看到的大多数知识点，其实都挂在这条线上。

## 第一部分：先建立分层视角

JavaGuide 会先强调 `OSI` 和 `TCP/IP` 分层模型，小林 coding 也会反复用“这一层解决什么问题”的方式来讲。对于初学者，重点不是死背七层，而是理解为什么要分层。

### 为什么要分层

因为网络问题太复杂，不拆层根本没法设计。

你可以类比前端工程：

- UI 层管展示
- 状态层管数据
- 网络层管请求

网络也是一样，只不过它把“通信”拆成几层来处理。

### 最实用的五层理解

- 应用层：离用户最近，定义“你到底在传什么”
- 传输层：解决“进程到进程怎么通信”
- 网络层：解决“机器到机器怎么找到路”
- 数据链路层：解决“同一段链路上怎么传”
- 物理层：解决“比特怎么变成电信号/光信号”

### 每层可以先粗暴理解成什么

- 应用层：`HTTP`、`DNS`、`SMTP`
- 传输层：`TCP`、`UDP`
- 网络层：`IP`
- 链路层：以太网、`MAC`
- 物理层：网线、光纤、无线电波

这里最关键的感觉是：

**应用层负责业务语义，TCP/IP 负责把这些语义可靠送过去。**

## 第二部分：从“访问一个网页”串起全局

JavaGuide 有一篇“访问网页的全过程”，这是特别好的串联主线。你可以把大部分知识点都挂在这个场景上。

### 当你输入一个网址时，发生了什么

可以按这个顺序理解：

1. 浏览器先解析 URL
2. 看看本地有没有缓存的 DNS 结果
3. 没有的话去做 DNS 查询，拿到目标 IP
4. 浏览器和服务器建立 TCP 连接
5. 如果是 HTTPS，还要做 TLS 握手
6. 浏览器发送 HTTP 请求
7. 服务器返回 HTTP 响应
8. 浏览器解析内容并渲染页面
9. TCP 连接关闭，或者复用

这条链路几乎把网络核心点全带出来了：

- `DNS`
- `IP`
- `TCP`
- `HTTPS`
- `HTTP`
- 长连接和连接复用

## 第三部分：IP 解决“机器和机器怎么找到彼此”

### IP 在做什么

你可以把 `IP` 理解成“网络世界里的地址系统 + 转发规则”。

现实里寄快递，先得知道收件地址。网络里发数据，也得知道目标机器在哪。

### IP 层关心的核心问题

- 数据包发给谁
- 经过哪些路由器转发
- 最终能不能到目标机器

### IP 不保证什么

**IP 只负责尽力送，不保证一定送到，也不保证顺序。**

所以可靠性不是 IP 负责的，而是上面的 `TCP` 去补。

### 你需要顺便建立的几个概念

- `IP` 地址：逻辑地址
- `MAC` 地址：局域网里网卡的物理地址
- 路由器：帮你决定下一跳往哪走
- `ARP`：已知 IP，找同一局域网里对应的 MAC
- `NAT`：把内网地址映射成公网地址

很多人网络学不顺，是因为 `IP`、`MAC`、端口、域名这些地址概念混成一团。你可以这样分：

- 域名：给人看的名字
- IP：给网络层找机器
- 端口：给传输层找进程
- MAC：给链路层找网卡

## 第四部分：TCP 和 UDP 解决“程序和程序怎么通信”

先不要急着背区别，先问自己一个问题：同样是传数据，为什么要有两套协议？因为场景不同。

### UDP 的感觉

`UDP` 更像“直接发语音消息”：

- 不保证对方收到
- 不保证顺序
- 开销小
- 速度快

适合对实时性要求高、但允许少量丢失的场景，比如音视频、直播、游戏。

### TCP 的感觉

`TCP` 更像“带回执、按顺序编号、还能重发的快递系统”：

- 面向连接
- 保证可靠传输
- 保证有序
- 有流量控制和拥塞控制

适合网页、数据库、RPC、大多数业务系统。

### TCP 为什么可靠

你可以先只记住四件事：

- 序列号：保证顺序
- 确认应答：告诉你收到了
- 超时重传：没收到就再发
- 滑动窗口：不用每发一个都傻等

## 第五部分：三次握手和四次挥手到底在解决什么

### 三次握手

它本质上是在确认两件事：

- 你能发给我吗
- 我能发给你吗

粗暴记忆方式：

- 第一次：客户端说“我想连你”
- 第二次：服务端说“我收到了，我也能回你”
- 第三次：客户端说“我也收到你的回复了”

### 四次挥手

因为 TCP 是全双工的，双方都可以发数据，所以关闭连接时是分开确认的。

### 为什么 TIME_WAIT 常被问

你先记一个很实用的理解：

- 防止最后一个 ACK 丢失
- 防止旧连接里的报文影响新连接

## 第六部分：HTTP 是最常见的应用层协议

`HTTP` 定义的是：

- 请求怎么发
- 响应怎么回
- 方法、状态码、Header 怎么表达语义

所以 `HTTP` 不是“怎么连上去”，而是“连上之后按什么格式聊天”。

### 学 HTTP 的主线

- 请求行、响应行、Header、Body
- 常见方法：`GET`、`POST`、`PUT`、`DELETE`
- 常见状态码：`200`、`301`、`302`、`400`、`401`、`403`、`404`、`500`
- 无状态和 Cookie/Session
- 长连接
- 缓存

### HTTP 版本怎么理解

- `HTTP/1.0`：基本能用，但连接复用差
- `HTTP/1.1`：默认长连接，实用很多
- `HTTP/2`：多路复用、头部压缩，更高效
- `HTTP/3`：基于 `QUIC`，继续优化传输体验

## 第七部分：HTTPS 为什么更安全

更完整一点的理解是：

`HTTPS = HTTP + TLS`

`TLS` 大致解决三件事：

- 加密：别人看不懂
- 完整性：别人篡改了你能发现
- 身份认证：确认你连的是对方，不是中间人

## 第八部分：DNS 是网络里的电话簿

人记域名，机器更适合用 IP，所以 DNS 就是在做：

**把域名翻译成 IP。**

它几乎是网络请求的起点，也很容易引出缓存、递归查询、迭代查询、CDN 调度这些问题。

## 第九部分：Socket 是程序操作网络的入口

从开发视角看，真正写代码时，你不会直接去操作 `TCP` 协议字段，更常接触的是 `Socket`。

你可以把它理解成：

**操作系统提供给应用程序的一套网络通信接口。**

## 第十部分：为什么服务端高并发离不开 IO 多路复用

如果一个线程只盯一个连接，那连接一多，线程就爆了。所以操作系统要提供一种机制：

**一个线程能同时盯很多连接，谁准备好了就处理谁。**

这就是 IO 多路复用的意义。

先知道这三个名字就够了：

- `select`
- `poll`
- `epoll`

## 第十一部分：怎么把这些知识真正串成体系

### 第一轮：先建地图

- 什么是五层模型
- 一次访问网页经历什么
- `IP`、端口、域名、`MAC` 分别是什么
- `TCP` 和 `UDP` 分别适合什么场景

### 第二轮：吃透高频协议

- `TCP` 三次握手、四次挥手
- 可靠传输
- 流量控制和拥塞控制
- `HTTP` 和 `HTTPS`
- `DNS`

### 第三轮：补高性能服务端视角

- Socket
- 阻塞/非阻塞
- IO 多路复用
- `select/poll/epoll`
- 长连接、连接池、心跳

## 一个适合背诵的知识框架

“计算机网络本质上是解决程序之间如何可靠通信的问题。为了降低复杂度，网络采用分层设计，应用层负责定义业务协议，比如 HTTP 和 DNS；传输层主要是 TCP 和 UDP，解决进程间通信；网络层通过 IP 解决机器寻址和路由；再往下是链路层和物理层。实际开发里，最常见的链路是用户输入 URL，先做 DNS 解析拿到 IP，再通过 TCP 建立连接，如果是 HTTPS 还要做 TLS 握手，之后再发送 HTTP 请求。TCP 通过序列号、确认应答、重传和滑动窗口保证可靠传输，而服务端在高并发场景下通常要结合 Socket 和 IO 多路复用来高效处理大量连接。” 

## 学这块最容易踩的坑

- 一上来就背七层模型，结果不知道每层解决什么问题
- 把 `HTTP` 当成“网络本身”，忽略 `TCP/IP`
- 背了三次握手，但不知道握手是在确认什么
- 知道 `HTTPS` 更安全，但说不出安全到底体现在哪
- 知道 `epoll` 更强，但说不出它解决了什么现实问题
