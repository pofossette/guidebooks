# 01. Elasticsearch 基础与定位

学 ES 的第一步，不是 DSL 语法，而是先知道它该放在系统的哪一层。

## 一、Elasticsearch 适合做什么

最常见的几类场景：

- 站内搜索
- 商品搜索
- 日志检索
- 全文检索
- 标签、条件、范围组合筛选

## 二、Elasticsearch 不适合做什么

### 1. 强事务主业务库

### 2. 所有业务都直接依赖它作为唯一事实来源

### 3. 完全替代关系型数据库

ES 更适合做：

- 检索层
- 搜索层
- 分析层

而不是最核心的权威数据源。

## 三、ES 在系统里的典型位置

最常见做法是：

- 主数据存在 PostgreSQL / MySQL / MongoDB
- 搜索索引同步到 Elasticsearch
- 查询搜索走 ES

## 四、为什么很多系统要“数据库 + ES”双存

因为两者擅长的事情不同：

- 数据库负责正确存储
- ES 负责更强搜索体验

## 这篇最重要的结论

Elasticsearch 最重要的定位，是搜索和分析引擎，而不是“直接替代业务数据库”的方案。
