# 06. Elasticsearch 的适用边界与工程使用建议

很多团队第一次上 ES，最容易犯的错误就是：

**把它想成“什么都能顺便做的数据库”。**

这通常会出问题。

## 一、ES 最适合承担什么角色

- 搜索引擎
- 检索层
- 日志分析平台
- 文本和条件组合查询引擎

## 二、ES 最不适合承担什么角色

- 唯一主业务数据源
- 强事务核心账务系统
- 高频复杂更新的权威主库

## 三、工程上最常见的双写模式

很多系统会采用：

- 数据库写主数据
- 异步同步到 ES

这意味着你还要考虑：

- 同步延迟
- 索引更新失败
- 搜索和主库短暂不一致

## 四、一个务实建议

先把 ES 当成“增强搜索能力的专用系统”，而不是“把原数据库替换掉的万能方案”。

## 这篇最重要的结论

Elasticsearch 的价值很强，但边界也很清晰。用对位置，它能显著提升搜索体验；用错位置，它会让数据一致性和系统复杂度一起上升。
