# 03. 超时、重试、幂等与补偿

很多故障不是因为一次调用失败，而是因为失败之后处理得太差。

## 一、为什么超时很重要

如果没有超时：

- 请求可能一直卡住
- 线程和连接被长期占着
- 故障会像堵车一样层层往上传

所以超时本质上是在给系统设边界。

## 二、重试是在解决什么问题

重试适合处理“临时性失败”。

例如：

- 短暂网络抖动
- 下游瞬时不可用
- 短时超时

但重试不是越多越好。

## 三、为什么重试很容易把问题变更糟

如果下游已经很慢，你还无脑重试：

- 流量会被放大
- 下游压力更大
- 故障更难恢复

所以正确重试通常要配：

- 次数上限
- 退避策略
- 幂等保障

## 四、幂等是在解决什么问题

幂等的目标是：

**同一个请求重复执行多次，结果尽量一致。**

这在高可用里特别重要，因为：

- 网络可能超时
- 客户端可能重发
- 服务端可能重试
- 消息队列可能重复投递

## 五、哪些场景必须考虑幂等

- 支付回调
- 下单创建
- 库存扣减
- 任务消费
- 第三方通知

## 六、补偿是在解决什么问题

有些流程跨多个系统，很难靠一个本地事务全包住。

这时就要考虑：

- 某一步成功了
- 后面一步失败了
- 要怎么把状态拉回合理结果

这就是补偿思路。

## 七、超时、重试、幂等、补偿之间是什么关系

可以这样理解：

- 超时：别无限等
- 重试：失败了再试一次
- 幂等：重试不能把数据做乱
- 补偿：真失败了要有收尾方案

## 八、一个典型链路

1. 调下游接口前设超时
2. 发生临时失败后有限重试
3. 用幂等键避免重复执行副作用
4. 如果跨系统部分成功，再做补偿或状态修正

## 九、最容易犯的错误

### 1. 所有失败都重试

有些失败是逻辑错误，重试没有意义。

### 2. 重试没有上限

### 3. 只做重试，不做幂等

### 4. 跨系统流程只讲成功路径，不讲补偿

## 这篇最重要的结论

高可用不仅是让请求成功，更是让失败可控。超时负责止损，重试负责恢复，幂等负责不乱，补偿负责收尾。
