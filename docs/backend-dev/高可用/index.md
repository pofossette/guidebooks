# 高可用

这一组文档参考 `JavaGuide` 的高可用栏目来写，重点不是讲“系统有多大”，而是讲：

**系统出问题时，为什么不会一下子全挂。**

高可用关注的核心不是速度，而是稳定性和恢复能力。

## 基本思路

可以先把高可用理解成 5 个很具体的问题：

### 1. 请求太多怎么办

- 限流
- 排队
- 削峰

### 2. 下游变慢怎么办

- 超时
- 重试
- 熔断
- 隔离

### 3. 核心服务挂了怎么办

- 降级
- 冗余
- 故障转移

### 4. 重复请求怎么办

- 幂等
- 防重
- 状态机

### 5. 上线前怎么证明系统扛得住

- 压测
- 监控
- 演练
- 容量评估

如果把这 5 个问题抓住，高可用这部分就不会再是一堆零散名词。

## 推荐顺序

1. 先看基础和 SLA，建立高可用目标感。
2. 再看“请求太多”和“下游变慢”这两类问题：限流、削峰、超时、重试、熔断、隔离。
3. 接着看“核心服务挂了”和“重复请求”这两类问题：降级、冗余、故障转移、幂等、防重、状态机。
4. 最后看压测、监控、演练和容量评估，把高可用落到可验证的工程动作上。
