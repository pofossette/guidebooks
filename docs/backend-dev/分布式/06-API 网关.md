# 06. API 网关

## 一、什么是 API 网关

API 网关是客户端和后端服务之间的一层入口。

它的核心作用是：

**把外部请求统一接进来，再转发到后端合适的服务。**

如果没有 API 网关，客户端可能要直接知道：

- 用户服务地址
- 订单服务地址
- 支付服务地址
- 文件服务地址

服务一多，客户端会非常痛苦。

## 二、API 网关解决什么问题

常见能力包括：

- 统一路由
- 认证鉴权
- 限流
- 熔断降级
- 请求聚合
- 协议转换
- 日志和监控
- 灰度发布

它不是简单的反向代理，而是面向 API 流量治理的一层。

## 三、网关和负载均衡有什么区别

| 组件 | 关注点 |
|---|---|
| 负载均衡 | 把流量分发到多个实例 |
| API 网关 | 管理 API 入口、鉴权、限流、路由、观测 |

Nginx 可以做负载均衡，也可以承担部分网关能力。但大型系统通常会引入更完整的网关产品。

## 四、API 网关常见功能

## 4.1 路由

例如：

- `/api/users/**` 转发到用户服务
- `/api/orders/**` 转发到订单服务
- `/api/payments/**` 转发到支付服务

## 4.2 鉴权

网关可以统一校验：

- JWT
- Session
- API Key
- OAuth Token

这样后端服务不用重复写基础鉴权逻辑。但服务内部仍然要做业务权限校验。

## 4.3 限流

网关可以限制：

- 单个用户每分钟请求数
- 单个 IP 请求数
- 某个接口整体 QPS

限流可以防止恶意请求或突发流量打垮后端。

## 4.4 请求聚合

客户端一个页面可能需要：

- 用户信息
- 订单列表
- 优惠券
- 推荐商品

网关或 BFF 层可以聚合多个后端请求，减少客户端复杂度。

## 五、API 网关和 BFF

`BFF` 是 Backend For Frontend。

区别可以这样理解：

- API 网关偏通用基础设施入口
- BFF 偏为某一类前端页面组织接口

例如：

- 网关负责鉴权、限流、路由
- Web BFF 负责把多个后端接口组合成页面需要的数据
- App BFF 负责移动端字段裁剪和兼容

## 六、常见产品

| 产品 | 说明 |
|---|---|
| Nginx | 反向代理、负载均衡，可做简单网关 |
| Kong | 插件丰富的 API 网关 |
| Apache APISIX | 高性能云原生 API 网关 |
| Envoy | 常用于服务网格和边车代理 |
| Spring Cloud Gateway | Java 生态常见网关 |

## 七、TS 后端中的位置

TS 后端项目里，常见组合是：

- Nginx/APISIX/Kong 作为统一入口
- NestJS/Express/Fastify 提供业务 API
- BFF 用 Node.js 编写，服务具体前端场景

如果你正在学 Node 后端，不建议一开始就手写完整网关。你更应该先理解：

- 网关负责什么
- 服务内部还要负责什么
- 鉴权、限流、日志应该放在哪里

## 八、网关不是万能的

常见误区：

- 把所有业务逻辑塞进网关
- 认为网关鉴权后服务内部就不用管权限
- 网关规则变得过多，没人敢改

更稳的边界是：

- 网关做通用入口治理
- BFF 做前端适配
- 业务服务做业务规则和数据一致性
