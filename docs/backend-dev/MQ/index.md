# MQ

这一组文档面向已经有一点后端或 TypeScript 基础、但希望系统补齐消息队列知识体系的开发者。

结构上参考 `JavaGuide` 那种按专题拆分的知识地图，同时吸收 `小林 coding` 常见的“问题驱动 + 面试高频追问”写法。

目标不是替代官方文档，而是先帮你把 MQ 的主线建立起来：

**为什么要用 MQ -> 消息怎么投递和消费 -> 为什么会重复 / 丢失 / 堆积 -> 怎样做幂等和最终一致性 -> 怎样在 Kafka、RabbitMQ、RocketMQ 之间做选择**

- JavaGuide 分布式高频面试题总结: https://interview.javaguide.cn/distributed-system/distributed-system.html

## 推荐顺序

1. 先看概念速览和“为什么要用 MQ”，把它放回系统设计语境里理解。
2. 再看消息模型、可靠性、幂等和顺序问题，这些是实际开发最容易踩坑的部分。
3. 接着看最终一致性和中间件选型，把 MQ 从“会背名词”推进到“能写方案”。
4. 最后看工程实践和面试高频问题，用真实链路把知识串起来。

## 学习提醒

- 不要把 MQ 只理解成“异步工具”，它本质上还是一套流量整形、系统解耦和可靠传递机制。
- 不要一上来就背 `Kafka`、`RocketMQ` 内部细节，先搞清业务到底需要吞吐、顺序、延迟还是事务能力。
- 不要只会画架构图，不会回答“消息丢了怎么办”“重复消费怎么办”“为什么会积压”。
