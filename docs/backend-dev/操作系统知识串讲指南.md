# 操作系统知识串讲指南

这篇文档参考了 `JavaGuide` 的操作系统专题和 `小林 coding` 的图解系统写法，目标是帮你快速把操作系统知识串起来，形成一张能解释很多后端问题的底层地图。

如果说计算机网络是在解决“机器之间怎么通信”，那操作系统解决的就是：

**一台机器上的 CPU、内存、磁盘、文件、进程、线程，到底怎么被管理起来。**

很多人学操作系统时容易有个误区：觉得它很底层，离业务远。实际上恰好相反。

你平时开发里遇到的很多问题，本质上都和操作系统有关：

- 为什么线程多了反而变慢？
- 为什么高并发服务常提 `epoll`？
- 为什么会有死锁？
- 为什么内存明明很多，程序还是 OOM？
- 为什么一个进程崩了会影响整个服务？
- 为什么数据库、Redis、Nginx 都在强调 IO 模型？

## 这门课的主线是什么

如果只记一条主线，记这个：

**CPU 怎么分给任务 -> 内存怎么分给程序 -> 进程线程怎么协作 -> IO 怎么高效处理 -> 文件怎么组织和持久化**

## 第一部分：先搞清操作系统到底在做什么

`操作系统 = 硬件和应用程序之间的中间层。`

你可以把它理解成“总调度员 + 总管家”。

它要管很多事：

- 谁先用 CPU
- 哪块内存分给谁
- 谁能访问磁盘
- 程序之间怎么隔离
- 文件怎么存
- 网络 IO 怎么处理

## 第二部分：先建立“进程”和“线程”的主线

### 为什么会有进程

因为机器上通常不只跑一个程序。浏览器、编辑器、终端、数据库、后端服务，都得一起跑。操作系统要想办法让它们互不干扰，还能合理分资源。

### 进程可以先粗暴理解成什么

**一个正在运行的程序实例。**

它有自己的：

- 地址空间
- 打开的文件
- 资源信息
- 运行状态

### 为什么还要有线程

因为一个进程里，很多任务可以并发干。

### 最实用的区别记法

- 进程：资源分配的基本单位
- 线程：CPU 调度的基本单位

线程共享进程的大部分资源，但每个线程有自己的栈和程序计数器。

## 第三部分：CPU 调度到底在调什么

单核 CPU 某一时刻其实只能执行一个线程，但操作系统会快速切换执行对象，所以你感觉很多程序在同时运行。

调度在做什么：

- 现在轮到谁执行
- 执行多久
- 什么时候切走

### 为什么线程太多反而变慢

因为线程切换不是免费的。每次切换，都可能涉及保存现场、恢复现场、CPU Cache 命中率下降。

这就是上下文切换。

## 第四部分：进程之间怎么通信

既然进程彼此隔离，那它们怎么协作？这就引出了 IPC，也就是进程间通信。

### 常见方式可以先这样记

- 管道：简单、父子进程常见
- 消息队列：按消息传
- 共享内存：最快，但同步难
- 信号量：用于同步和互斥
- Socket：最通用，本机和跨机器都能用

## 第五部分：锁和死锁为什么总被问

### 为什么要加锁

多个线程同时改同一个数据，如果不加控制，结果就乱了。

### 常见锁你可以先这样理解

- 互斥锁：拿到锁的人独占
- 自旋锁：不睡觉，一直转着等
- 读写锁：读可以共享，写必须独占

### 什么是死锁

**大家都在等别人先放手，结果谁也走不了。**

### 死锁四个必要条件

- 互斥
- 请求并保持
- 不可剥夺
- 循环等待

## 第六部分：内存管理是操作系统的另一条大主线

先搞清楚目标：

**让程序觉得自己有一大片连续内存可用，同时别互相打架，系统还能高效利用物理内存。**

### 为什么要有虚拟内存

因为物理内存是有限、离散、会冲突的。

### 你可以先这样理解虚拟内存

- 程序看到的是虚拟地址
- 操作系统和硬件负责把虚拟地址映射到物理地址

这就引出了页表、分页、缺页中断这些概念。

### 缺页中断是什么

当程序访问的页现在不在物理内存里，就会触发缺页中断，操作系统再把它调进来。

## 第七部分：为什么会有用户态和内核态

### 最直白的理解

- 用户态：权限低，运行普通应用
- 内核态：权限高，可以直接管硬件和核心资源

### 系统调用是什么

应用程序如果想做高权限操作，比如创建进程、申请内存、读写文件、发网络包，就得通过系统调用向内核申请。

## 第八部分：文件系统在解决什么问题

它要回答的是：

- 文件怎么组织
- 文件内容放在哪
- 怎么查找
- 怎么做权限管理
- 删除之后为什么空间能回收

### 一个很重要的概念：inode

你可以先把 `inode` 理解成“文件的身份证”。

## 第九部分：IO 模型为什么和后端性能强相关

### 常见 IO 模型

- 阻塞 IO
- 非阻塞 IO
- IO 多路复用
- 信号驱动 IO
- 异步 IO

### 为什么 IO 多路复用这么重要

因为高并发服务端不可能一个连接配一个线程无限扩张。

更现实的做法是：

- 一个线程盯很多连接
- 谁就绪了处理谁

这就是 `select`、`poll`、`epoll` 这条线。

## 第十部分：零拷贝为什么总和高性能系统绑在一起

数据在磁盘、内核缓冲区、用户缓冲区、网卡之间来回搬运，拷贝多了就贵。

零拷贝想解决的是：尽量减少不必要的数据复制和用户态/内核态切换。

## 第十一部分：怎么把操作系统知识真正串起来

### 第一轮：先建大框架

- 操作系统是什么
- 进程和线程是什么
- 用户态和内核态是什么
- 虚拟内存是什么
- 文件系统在干嘛

### 第二轮：吃透主链路

- 进程/线程/调度
- 锁/同步/死锁
- 虚拟内存/分页/缺页
- 系统调用
- IO 模型

### 第三轮：把它和后端开发连起来

- 为什么线程池不能乱配
- 为什么高并发服务要看上下文切换
- 为什么 Java、Go、Node.js 都在谈调度和 IO
- 为什么数据库和 Redis 会受页缓存、IO 模型影响

## 一个适合背诵的串讲框架

“操作系统本质上是管理硬件和软件资源的中间层，主要负责 CPU 调度、内存管理、进程线程管理、文件系统和 IO。进程是资源分配的基本单位，线程是调度的基本单位，多线程共享进程资源但也会带来同步问题，所以又引出了锁和死锁。内存管理的核心是虚拟内存和分页机制，它让程序觉得自己有独立连续的地址空间，同时通过页表映射到物理内存。为了保证安全和稳定，操作系统又区分了用户态和内核态，应用程序需要通过系统调用访问内核能力。高并发服务端则高度依赖操作系统提供的 IO 多路复用能力，比如 epoll，这也是 Redis、Nginx 这类高性能系统的重要基础。” 

## 学这块最容易踩的坑

- 背了很多名词，但不知道它们在解决什么问题
- 只会说进程线程区别，讲不出为什么线程切换更轻
- 死锁四条件会背，但不会联系真实加锁场景
- 知道虚拟内存，却不知道它为什么存在
- 听过 `epoll`，但说不出它对高并发到底帮助在哪
