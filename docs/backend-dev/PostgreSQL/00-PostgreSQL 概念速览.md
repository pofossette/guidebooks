# 00. PostgreSQL 概念速览

这一篇只做一件事：帮你在正式进入细节前，先把 PostgreSQL 的核心概念记住。

## 一、PostgreSQL 是什么

PostgreSQL 是一个开源关系型数据库。

但如果只记“关系型数据库”还不够，因为它还有几个非常重要的工程标签：

- 事务能力强
- SQL 能力完整
- 扩展能力强
- 对 `jsonb`、全文检索、地理数据、向量扩展支持好

所以你可以先把它理解成：

**一个适合做业务主库，同时又能兼顾复杂查询和部分新型数据场景的数据库。**

## 二、为什么现在很多后端项目会选 PostgreSQL

原因通常不是“它更潮”，而是它在工程上比较均衡：

- 既能做传统事务系统
- 也能处理复杂查询
- 还能把部分半结构化数据放进同一套库里

典型场景：

- 用户、订单、支付、会话等业务主数据
- 后台管理系统的复杂筛选和聚合
- 带 `jsonb` 元数据的业务记录
- AI/Agent 场景下的结构化数据、检索元数据、向量扩展

## 三、学习 PostgreSQL 要抓哪条主线

建议按这条线学：

**数据类型与表设计 -> SQL 查询 -> 索引 -> 执行计划 -> 事务与 MVCC -> 锁与并发 -> WAL 与可靠性 -> 性能优化 -> 高可用与扩展**

原因很简单：

- 设计不对，后面越优化越累
- 索引不会，SQL 很容易慢
- 事务和锁不懂，系统一上并发就出错
- WAL 和复制不懂，线上事故会看不明白

## 四、PostgreSQL 和 MySQL 学习上的最大区别

共同点很多：

- 都要学表、SQL、索引、事务、锁、执行计划
- 都是后端开发的核心数据库基础

不同点也很明显：

- PostgreSQL 的扩展能力更强
- `jsonb`、`GIN`、全文检索更常见
- `MVCC`、`VACUUM`、WAL 这些概念更值得单独理解
- 很多教程默认用 MySQL 举例，所以学 PG 时要主动建立自己的术语体系

## 五、你现在最该先记住哪些关键词

- `row` / `tuple`：一行数据
- `index`：帮助更快定位数据
- `planner`：决定执行计划的优化器
- `MVCC`：多版本并发控制
- `WAL`：预写日志，保证可靠性
- `checkpoint`：把脏页和日志推进到稳定状态
- `vacuum`：清理旧版本，回收空间

先不用把它们背得很细，但你要知道这些词分别属于哪一层。

## 六、初学者最容易犯的三个误区

### 1. 只学 SQL，不学表设计

真实项目里，很多性能和维护问题都不是 SQL 语法错，而是表结构一开始就没设计好。

### 2. 只学索引，不看执行计划

索引建了不代表一定会用。数据库最终怎么跑，还是要看执行计划。

### 3. 把事务和锁混为一谈

事务是为了保证一组操作的正确性，锁是并发控制手段。它们相关，但不是同一个东西。

## 七、这一专题怎么读

如果你是从前端转后端，推荐这么看：

1. 先看 `01` 和 `02`，建立表设计与数据库模块认知。
2. 再看 `03` 到 `05`，把“写 SQL”和“优化 SQL”连起来。
3. 接着看 `06` 到 `08`，补齐并发与可靠性。
4. 最后看 `09`，理解线上系统为什么要监控、复制、扩展。

## 这篇最重要的结论

PostgreSQL 不只是一个“存数据的地方”，它本质上是后端系统里承载事实数据、事务语义、查询能力和可靠性机制的核心基础设施。
