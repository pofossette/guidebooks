# PostgreSQL

这一组文档面向已经有一点后端或 TypeScript 基础、但希望系统补齐 PostgreSQL 的开发者。形式上参考 `JavaGuide` 的知识地图拆分方式，以及 `小林 coding` 那种先讲“为什么要有这个东西”，再讲“它是怎么工作的”的写法。

这组内容的目标不是替代官方文档，而是帮你把 PostgreSQL 的主线建立起来：

**会写 SQL -> 会做表设计 -> 会建索引 -> 会看执行计划 -> 会处理事务并发 -> 会做性能优化和工程落地**

## 推荐顺序

1. 先看概念速览和体系总览，建立 PostgreSQL 的整体地图。
2. 再看表设计、SQL 和索引，这三块决定了你能不能把业务系统写稳。
3. 接着看执行计划、事务和锁，补齐性能与并发排障能力。
4. 最后再看可靠性、高可用和扩展，把知识从“会用”推进到“能做工程方案”。

## 学习提醒

- 不要一上来钻实现细节，先建立“模块在解决什么问题”的认知。
- 不要把 PostgreSQL 只当成“另一个 MySQL”，它在 `jsonb`、全文检索、扩展能力上有明显特点。
- 不要把数据库问题只理解成 SQL 语法问题，真实项目里更多是表设计、索引选择、并发控制和资源分配问题。
