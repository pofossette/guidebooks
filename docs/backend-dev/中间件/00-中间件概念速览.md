# 00. 中间件概念速览

这一篇只做一件事：先把“中间件”放回正确语境里理解。

## 一、中间件到底是什么

中间件不是某个具体库，而是一类处理方式：

**在真正的业务 handler 之前、之中或之后，插入一段可复用的横切逻辑。**

最常见的横切逻辑包括：

- 记录日志
- 生成 `requestId`
- 鉴权
- 参数校验
- 限流
- 错误收敛
- 安全头处理

这些逻辑往往不属于某一个业务接口本身，但很多接口都需要。

## 二、为什么后端需要中间件

如果没有中间件或等价机制，代码很快会变成这样：

- 每个路由都手写鉴权
- 每个路由都手写日志
- 每个路由都手写错误格式
- 每个路由都各自解析上下文

结果就是重复、分散、难维护。

所以中间件的核心价值是：

- 抽复用
- 统一行为
- 缩短业务 handler
- 把横切逻辑放到固定位置

## 三、在 Node.js 里它不止一种形式

很多人一说中间件，脑子里只有 `Express`：

```ts
app.use((req, res, next) => {
  next();
});
```

但在 `Fastify` 里，真正更常用的其实是：

- `hook`
- `plugin`
- `decorate`
- schema 校验

所以“中间件”在 `Fastify` 语境里，常常是一个广义词，不一定只指 `use()`。

## 四、这类逻辑一般放在哪

可以先用最粗的方式记：

| 逻辑类型 | 常见落点 |
|---|---|
| 原始 `req/res` 处理 | middleware |
| 请求生命周期控制 | hook |
| 功能打包与注册 | plugin |
| 上下文能力挂载 | decorate |
| 参数和返回约束 | schema + TypeScript |

## 五、你最该先防的误区

### 1. 把所有横切逻辑都塞进路由

这样短期方便，长期一定臃肿。

### 2. 把 `Fastify hook` 和 `Express middleware` 当成同一个东西

它们相似，但不是一回事。

### 3. 只会装插件，不知道插件是在解决哪一层问题

会配 `@fastify/cors` 不等于真正理解了跨域在请求链路的哪个位置生效。
