# 04. 索引设计与查询优化

MongoDB 慢查询的根源，和关系型数据库很像：

- 没索引
- 索引用错
- 查询条件和排序不匹配

## 一、为什么 MongoDB 也必须认真学索引

因为文档模型再灵活，数据量一上来，最终也绕不开：

- 怎么更快找到目标文档
- 怎么减少扫描范围
- 怎么让排序不那么贵

## 二、常见索引类型先记哪些

- 单字段索引
- 复合索引
- 唯一索引
- 文本索引

## 三、复合索引为什么重要

很多查询不是只按一个字段查，而是：

- 先按条件过滤
- 再按时间排序

这时索引顺序就很重要。

## 四、MongoDB 查询优化最该先看什么

1. 高频查询条件
2. 排序字段
3. 返回量大小
4. 是否扫了太多不需要的文档

## 五、一个务实建议

不要先背所有索引种类，先围绕你的高频查询模式建索引。

## 这篇最重要的结论

MongoDB 的索引优化和关系型数据库一样，本质都是把查询路径翻译成更小的扫描范围。离开查询模式谈索引，意义不大。
