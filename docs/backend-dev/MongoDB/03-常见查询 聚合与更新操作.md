# 03. 常见查询、聚合与更新操作

MongoDB 日常开发最常见的事情，不是复杂分布式问题，而是：

- 查文档
- 改文档
- 聚合统计

## 一、最常见查询

通常是这些：

- 按 `_id` 查一条
- 按条件筛选列表
- 按时间排序
- 分页查询

## 二、MongoDB 查询和 SQL 的思维差别

SQL 更像在表上做集合操作。

MongoDB 更像在文档集合上做条件筛选和投影。

你要关心：

- 过滤条件
- 返回哪些字段
- 排序字段
- 分页方式

## 三、更新操作要注意什么

MongoDB 支持局部字段更新，这很方便。

但要注意：

- 是替换整个文档，还是只更新部分字段
- 并发更新会不会互相覆盖
- 高频写字段是否设计合理

## 四、聚合为什么重要

很多人只知道 MongoDB 能存文档，但忽略了聚合能力。

真实项目里很常见：

- 按状态统计数量
- 按时间维度聚合
- 过滤后再分组

这部分可以先理解成：

**MongoDB 也有一条自己的“数据处理流水线”。**

## 五、分页为什么也要认真设计

小数据量时随便翻页看不出问题。

大数据量时要关注：

- 排序字段是否有索引
- 分页是否会越翻越慢

## 这篇最重要的结论

MongoDB 的查询和聚合能力并不弱，但要围绕文档模型和索引来理解，而不是简单把它当“没有 SQL 的存储桶”。
