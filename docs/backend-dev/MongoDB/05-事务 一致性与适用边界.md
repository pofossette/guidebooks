# 05. 事务、一致性与适用边界

很多人对 MongoDB 的印象还停留在“灵活，但事务弱”。

这个印象已经不准确，但也不能走到另一个极端。

## 一、MongoDB 能不能做事务

能。

但学习重点不该是“有没有”，而是：

**什么时候值得用，代价是什么。**

## 二、为什么事务不是 MongoDB 的第一张牌

MongoDB 的优势更多在：

- 文档模型
- 灵活结构
- 对象化读写

而不是像传统关系型数据库那样，天然以强事务和复杂关联为核心卖点。

## 三、什么场景适合 MongoDB

如果你的业务：

- 更偏内容和对象数据
- 更偏文档读写
- 跨文档事务需求不重

MongoDB 会更自然。

如果你的业务：

- 强依赖复杂事务
- 强依赖多实体强一致更新

那就要更慎重。

## 四、通俗理解 MongoDB 的边界

MongoDB 不是不能做严肃业务，而是你要判断：

- 它是不是这个业务最顺手的主存储
- 你是因为建模匹配选它，还是因为“灵活省事”选它

## 这篇最重要的结论

MongoDB 现在具备事务能力，但它最核心的价值仍然不是“像关系型数据库一样用”，而是用文档模型解决更合适的问题。
