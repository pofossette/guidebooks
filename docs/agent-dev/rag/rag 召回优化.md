在检索增强生成（RAG）系统中，**“检索相关性低”**通常被称为“低召回”或“低精确度”，是导致大模型产生幻觉（胡说八道）的最核心原因——所谓“垃圾进，垃圾出（Garbage
in, garbage out）”。

针对检索相关性低的问题以及如何通过微调来进阶优化 RAG 系统，可以按以下策略系统性地解决：

一、 检索相关性低，如何优化召回？（免微调的工程优化）

在不改变现有大模型权重的前提下，可以通过检索前、检索中、检索后三个阶段的工程策略大幅提升相关性。

1. 检索前：数据与问题优化 (Pre-retrieval)

  - 提升数据信息密度：很多时候召回效果差是因为原始文档排版杂乱、包含冗余的页眉/页脚/水印，或者表格被错误解析。在入库前，建议使用工具（如大模型或专用解析器）将
    PDF/Word 转化为结构清晰的 Markdown 格式。
  - 智能分块策略（Chunking）：不要使用生硬的“按字数切断”。
      - 语义切分：尽量按段落或标点符号切分。
      - 滑动窗口：在两个相邻的文本块之间保留一定重叠（如50-100 token），防止关键上下文被生硬切断。
      - 父子文档切分：切分较小的“子块”用于精准匹配计算，但匹配中后，将包含该子块的完整“父文档块”送给大模型，保证语境完整。
  - 查询重写与扩展（Query Transformation）：用户的提问往往很短或缺乏主语。可以让大模型先对用户的输入进行“重写补充”。
      - HyDE（假设性文档嵌入）：让大模型先基于用户问题“盲猜”生成一个假答案，然后用这个假答案的向量去数据库里检索，这种做法往往能大幅提高语义匹配的相关性。

2. 检索中：召回策略优化 (Retrieval)

  - 混合检索（Hybrid Search）：这是解决相关性低的最有效手段。
      - **向量检索（Dense）**擅长理解语义（例如搜“手机”，能召回“智能移动设备”）。
      - **传统关键词检索（Sparse，如 BM25）**擅长精准匹配缩写、专有名词、编号（例如搜“iPhone 15
        Pro”，必须包含该型号字眼）。
      - 将两路结果融合，往往能兼顾语义和精准度。
  - 元数据过滤（Metadata
    Filtering）：在文档切片入库时，利用大模型提取诸如“时间、地点、作者、文档类别”等元数据打在标签上。检索时，先通过元数据硬过滤掉无关分类，再进行向量检索。

3. 检索后：重排序优化 (Post-retrieval)

  - 引入重排模型（Reranker）：这是立竿见影提升相关性的利器。向量检索为了速度往往只计算粗略的相关性。你可以先用向量检索粗召回前 50
    个块，然后引入专门的 Cross-Encoder 模型（如 bge-reranker 或 Cohere 的 Rerank
    API）针对“用户问题+文本块”进行交叉打分重排，精准筛选出得分最高的前 5 个块送给大模型。

二、 RAG 怎么微调优化？（高阶模型层优化）

如果你采用了上述所有的工程手段，但在特定垂直领域（如医疗、法律、特定企业内部制度）依然召回不准，因为通用模型根本不认识你们的“行业黑话”或产品代号。这时候就需要进行微调（Fine-tuning）。

RAG 的微调主要针对三大组件：

1. 微调嵌入模型（Embedding Fine-tuning）

通用向量模型（如 OpenAI 的 text-embedding-ada 或开源的 BGE-large）对你们公司的术语理解有限。

  - 怎么做：通过构建领域相关的正负样本对进行对比学习。
      - 正样本：{Query: "某缩写系统怎么登录", Document: "关于某系统登录指引..."}
      - 负样本：挑选那些“字面上相似但其实不回答该问题”的文档（即 Hard Negatives，困难负样本）。
  - 效果：微调后，系统能准确地将特定领域的“问题”和对应的“答案块”在多维向量空间中拉近距离。

2. 微调重排模型（Reranker Fine-tuning）

和微调 Embedding 类似，你可以针对重排器进行微调。

  - 怎么做：提供大量的 (Question, Relevant Context) 和 (Question, Irrelevant Context)
    数据对。通过交叉熵损失（Cross-Entropy Loss）训练 Cross-encoder
    架构的模型，让它学会区分在你们特定业务场景下，什么是真正的线索，什么是迷惑信息。

3. 微调生成模型（LLM Generator Fine-tuning / SFT）

在 RAG 中微调大语言模型（LLM），目的不是为了让它“死记硬背”知识，而是让它学会更好地利用检索到的上下文。

  - 拒答/抗幻觉训练：在微调数据集中故意掺杂毫不相关的检索片段，并将大模型的期望输出设为：“根据提供的参考资料，我无法回答该问题。”
    这能极大降低大模型在没有检索到相关知识时“强行胡编乱造”的概率。
  - 格式与信息提取对齐：训练大模型在看到大量且冗长的参考上下文时，学会提炼关键信息，并以公司要求的特定风格或格式（如表格、特定的话术结构）输出回复。

💡 最佳优化路径建议

不建议一开始就扎入微调的深坑。针对 RAG 的优化，性价比从高到低依次为： 清洗文档并优化切分 ➡️ 混合检索 (向量 + BM25) ➡️ 增加
Reranker 重排模型 ➡️ 使用 HyDE/查询重写 ➡️ 领域微调 Embedding/Reranker 模型 ➡️ 微调最终的生成大模型。
