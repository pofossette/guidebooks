# 分治、动态规划、二分搜索：通俗理解与经典例子

这三种方法经常一起出现，因为它们都在做一件事：**把大问题变小，再更高效地解决**。但它们的思路并不一样：

| 方法 | 一句话理解 | 关键特征 | 常见问题类型 |
| --- | --- | --- | --- |
| 分治 | 把问题拆成几块，分别解决，再合起来 | 子问题彼此相对独立 | 排序、树、递归计算 |
| 动态规划 | 小问题会重复出现，所以把答案记下来反复利用 | 重叠子问题、最优子结构 | 最值、方案数、状态转移 |
| 二分搜索 | 每次排除一半范围，快速缩小答案 | 有序性或单调性 | 查找、边界、最小可行值 |

如果只记一句话，可以记成：

- 分治像“分工合作”。
- 动态规划像“做过的题别再重做”。
- 二分搜索像“每次砍掉一半”。

## 1. 分治：先拆开，再合并

分治（Divide and Conquer）的核心是三步：

1. 把原问题拆成几个规模更小、结构相同的子问题。
2. 递归地解决这些子问题。
3. 把子问题的结果合并成原问题的答案。

可以把它理解成切西瓜：一个大西瓜不好一口吃完，那就切成几块分别吃，最后整件事就完成了。

### 什么时候适合分治

- 原问题可以自然拆成更小的同类问题。
- 子问题之间相对独立，不需要频繁共享中间结果。
- 合并步骤明确，能把小答案拼成大答案。

### 经典例子 1：归并排序

归并排序的过程非常典型：

1. 把数组从中间切成左右两半。
2. 左边排序，右边排序。
3. 把两个有序数组合并成一个更大的有序数组。

例如对 `[5, 2, 4, 1]` 排序：

1. 拆成 `[5, 2]` 和 `[4, 1]`
2. 再拆成 `[5] [2] [4] [1]`
3. 各自有序后合并成 `[2, 5]` 和 `[1, 4]`
4. 最后合并成 `[1, 2, 4, 5]`

它的关键不是“拆”，而是“**两个有序部分如何合并**”。

### 经典例子 2：快速排序

快速排序也属于分治：

1. 选一个基准值 `pivot`。
2. 把数组分成“小于它”和“大于等于它”的两边。
3. 递归处理左右两边。

它和归并排序一样都在“拆”，但合并方式不同。快速排序的重点在“划分”，归并排序的重点在“合并”。

### 经典例子 3：求二叉树深度

求一棵树的最大深度，也很像分治：

- 整棵树的深度 = `max(左子树深度, 右子树深度) + 1`

也就是把大树的问题交给左右子树，最后再把答案组合起来。

```typescript
type TreeNode = {
  left: TreeNode | null;
  right: TreeNode | null;
};

function maxDepth(root: TreeNode | null): number {
  if (!root) return 0;
  const leftDepth = maxDepth(root.left);
  const rightDepth = maxDepth(root.right);
  return Math.max(leftDepth, rightDepth) + 1;
}
```

### 分治最容易踩的坑

- 只会“拆”，不会“合并”，最后代码写成一堆递归但没有完整答案。
- 把所有递归都当成分治。其实递归只是写法，分治是一种解题思想。
- 忽略边界条件，比如数组长度为 0 或 1 时应直接返回。

## 2. 动态规划：算过一次，就别重复算

动态规划（Dynamic Programming, DP）最核心的想法是：

> 如果一个小问题会被反复计算，那就把它的答案存下来，后面直接拿来用。

它像做笔记。第一次推出来很费劲，但记下来后，后面遇到同样的小问题就不用再从头思考。

### 动态规划通常有两个信号

- **重叠子问题**：同一个小问题会反复出现。
- **最优子结构**：大问题的最优解，可以从小问题的最优解推出。

### 经典例子 1：爬楼梯

题目：每次可以爬 1 阶或 2 阶，爬到第 `n` 阶有多少种方法？

先看前几项：

- `f(1) = 1`
- `f(2) = 2`
- `f(3) = f(2) + f(1) = 3`
- `f(4) = f(3) + f(2) = 5`

为什么？

- 到第 `n` 阶的最后一步，要么从 `n - 1` 走 1 步过来，要么从 `n - 2` 走 2 步过来。
- 所以 `f(n) = f(n - 1) + f(n - 2)`。

这就是典型 DP。

```typescript
function climbStairs(n: number): number {
  if (n <= 2) return n;

  let prev2 = 1;
  let prev1 = 2;

  for (let i = 3; i <= n; i++) {
    const current = prev1 + prev2;
    prev2 = prev1;
    prev1 = current;
  }

  return prev1;
}
```

### 经典例子 2：零钱兑换

题目：给你若干硬币面额，凑出目标金额，最少需要多少枚硬币？

这类题的思路是：

- `dp[x]` 表示“凑出金额 `x` 的最少硬币数”。
- 对每个金额，尝试最后放入一枚硬币，看能不能从更小的金额转移过来。

这种题非常适合用来理解“**状态**”和“**状态转移**”。

### 经典例子 3：背包问题

背包问题几乎是动态规划的代表题。

- 物品有重量和价值。
- 背包容量有限。
- 问怎么选，才能让总价值最大。

它训练的是“有限资源下的最优选择”，很多面试题本质上都能抽象成背包。

### 动态规划该怎么想

做 DP 时，通常按这四步：

1. 定义状态：`dp[i]` 或 `dp[i][j]` 表示什么。
2. 写出转移：当前答案如何由更小状态推出。
3. 确定初始值：最小规模时答案是什么。
4. 确定计算顺序：先算谁，后算谁。

如果这四步说不清，代码通常也写不稳。

### 动态规划最容易踩的坑

- 一上来就写代码，没有先定义 `dp` 数组含义。
- 状态定义模糊，导致转移公式越写越乱。
- 把能贪心解决的问题硬写成 DP，复杂度白白变高。
- 明明是重复子问题，却还在用纯递归暴力搜索。

## 3. 二分搜索：每次砍掉一半

二分搜索（Binary Search）最朴素的场景，是在有序数组里找一个数。

比如要在下面数组里找 `23`：

`[3, 8, 12, 23, 31, 45, 57]`

做法不是从头一个个试，而是：

1. 先看中间值。
2. 如果中间值比目标小，说明答案只可能在右边。
3. 如果中间值比目标大，说明答案只可能在左边。
4. 每次都排除一半。

这就是二分搜索的本质：**利用有序性或单调性，快速缩小范围**。

### 经典例子 1：在有序数组中查找目标值

这是最标准的二分模板：

```typescript
function binarySearch(nums: number[], target: number): number {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) return mid;
    if (nums[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return -1;
}
```

### 经典例子 2：找第一个大于等于某值的位置

这类题比“找某个数”更常见，因为它是很多边界问题的基础，比如：

- 找第一个大于等于 `x` 的位置
- 找最后一个小于等于 `x` 的位置
- 统计某个数出现了多少次

它们本质上都在找“**边界**”。

### 经典例子 3：求平方根

例如求 `sqrt(10)` 的整数部分。

- 如果 `mid * mid <= 10`，说明答案至少是 `mid`。
- 如果 `mid * mid > 10`，说明答案更小。

虽然这里不是在数组里找元素，但答案区间是有序的，所以依然能二分。

### 经典例子 4：二分答案

这是二分最容易被忽视、但实战非常重要的一种用法。

比如题目问：

- 最小的运载能力是多少，才能在 `D` 天内运完货物？
- 最小的吃香蕉速度是多少，才能在规定时间内吃完？

这类题并不是“找某个现成的数”，而是：

- 猜一个答案 `mid`
- 检查这个答案是否可行
- 如果可行，尝试更小
- 如果不可行，尝试更大

只要“可行 / 不可行”随着答案变化呈现单调性，就能二分。

### 二分搜索最容易踩的坑

- 只记住“有序数组找数”，不知道“二分答案”。
- `left`、`right`、`mid` 更新不一致，导致死循环。
- 边界定义不清，不知道循环结束后该返回 `left` 还是 `right`。
- 忘记判断题目是否真的有单调性，结果强行二分。

## 4. 分治和动态规划有什么区别

这两个最容易混淆。

它们都在“拆问题”，但区别很关键：

| 对比点 | 分治 | 动态规划 |
| --- | --- | --- |
| 子问题关系 | 通常相对独立 | 经常重复出现 |
| 是否复用结果 | 一般不强调 | 强调复用 |
| 典型目标 | 把问题拆开处理 | 避免重复计算、求最优 |

最经典的对比是斐波那契数列：

- 用普通递归去算，是“拆问题”，但会重复算很多次。
- 用记忆化搜索或 DP 去算，才真正利用了重复子问题。

所以可以粗略记成：

- 子问题彼此独立，优先想分治。
- 子问题反复出现，优先想动态规划。

## 5. 遇到题目时，怎么判断该用哪一种

可以先问自己三个问题：

1. 能不能每次排除一半范围？
   如果能，优先考虑二分搜索。
2. 能不能把问题拆成几个更小的同类问题，最后再合并？
   如果能，考虑分治。
3. 小问题会不会重复出现？我是不是在反复求同一个状态？
   如果会，考虑动态规划。

很多题不只用一种思想。

- 归并排序是分治。
- 线段树查询里常带分治思路。
- “二分答案 + 贪心检查”是竞赛和面试里的高频组合。
- “记忆化搜索”本质上是带缓存的动态规划写法。

## 6. 一页速记

- 分治：拆开做，最后合并。代表题是归并排序、快速排序、树的递归问题。
- 动态规划：记住重复子问题的答案。代表题是爬楼梯、背包、零钱兑换。
- 二分搜索：每次排除一半。代表题是有序数组查找、边界查找、二分答案。

如果你是刚入门，建议按这个顺序练：

1. 二分搜索基础模板
2. 分治里的归并排序和树递归
3. 动态规划里的爬楼梯、打家劫舍、背包

这条路线最容易建立算法直觉。
